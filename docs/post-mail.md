# post-mail.md — 毎日の投稿文案をメールで届ける（＋判定の線）

作成日: 2026-10-11。**この1枚が正本**（仕組み・判定の線・👤の手順）。

## 結論

- `/ops` の「今日の投稿文案」（`/api/post-draft`・1日1本・KV の数値 → LLM）を、**毎日 12:00 JST に本人宛てメールで届ける**。メールの「X で投稿」を1回押すと、X の投稿画面が本文入りで開く。
- 消すのは2手だけ: ①サイトを開きに行く ②コピーして貼る。文案の作り方（発生源・プロンプト・1日1回の LLM 呼び出し）は変えていない。
- **自動投稿はしない**。リンクは投稿画面を開くだけで、送信ボタンは本人が押す。自動いいね・フォロー・返信・DM も無い。

## 仕組み

| 部品 | 場所 | 役割 |
|---|---|---|
| 定期実行 | `.github/workflows/post-mail.yml` | 毎時 :17 に起動。送るかどうかはスクリプトが判断する |
| 送信時刻 | `scripts/post-mail.config.json` の `send_hour_jst` | 初期値 `12`。**数字を書き換えて main に入れるだけで変更できる** |
| 本体 | `scripts/post-mail.mjs` | 文案を取得 → メールを組み立て → 送信（live のときだけ）→ 記録 |
| 文字数・リンク | `functions/api/_xtext.ts` | X の重み付き文字数（twitter-text 準拠・280）、280 を超えたら末尾を切る、`https://x.com/intent/tweet?text=` + URL エンコード |
| ガード | `functions/api/_postmail.ts` | 価格・有料版・アフィリエイト・メールアドレス・電話番号、**＋自分で登録した除外語**（勤務先名など）が入った文案は、本文を残したまま**リンクを外す** |
| 記録 | `/api/post-log`（KV `postlog:v1`） | 機械が日ごとの送信本数を記録。日曜に本人が `/ops` で投稿数と気持ち（5段階）を記録 |
| 判定の表示 | `/ops` の「発信の記録」 | 下の線をそのまま当てた結果を表示する（判定期間の途中では判定しない） |

- **既定は dry-run**: メールを組み立てて `out/post-mail/` に保存し（Actions では成果物として 14 日保管）、**送らない**。鍵が無い環境でもここまで動く。
- **停止スイッチ**: Variable `POST_MAIL_MODE=off` → 次の起動から何もしない（文案の取得もしない）。
- **1日1回**: 送信記録で同じ日の2回目を止め、さらに Resend の `Idempotency-Key`（`post-mail/日付`）で二重送信を防ぐ。
- 文案が作れなかった日（予算上限・鍵なし等）は、3時間再試行してから「作れませんでした（理由）」のメールを1通送る。黙って届かない日を作らない。
- 日曜のメールには、今週の記録（`/ops/#weekly`）へのリンクが付く。

### 送信手段の選定（Resend 無料枠 × GitHub Actions）

| 候補 | 👤の作業 | 費用 | 判断 |
|---|---|---|---|
| **GitHub Actions ＋ Resend（採用）** | Resend に登録 → 鍵を発行 → Secrets に2つ登録 | Actions は公開リポで無料。Resend 無料枠 3,000通/月（使うのは月30通） | 定期実行の形と `PUBLISH_TOKEN` が既にある（x-reply.yml と同じ形）。Resend はポートフォリオの標準メール手段（template-nextjs・reg-monitor）。**鍵は送信専用**で、漏れてもメールボックスには触れない。自分のアドレス宛てなら独自ドメインの認証が要らない |
| Actions ＋ Gmail SMTP（アプリパスワード） | 2段階認証の確認 → アプリパスワード発行 → Secrets に3つ登録 | 無料 | 鍵が**メールボックス全体の権限**になる（漏れたときの被害が大きい） |
| Cloudflare Email Routing（Workers の `send_email`） | ドメインのメール設定（MX）変更・宛先の認証・cron 用 Worker の別途作成 | 無料 | Pages には cron が無く、Worker の追加とドメイン設定の変更が要る。作業が最も多い |

## 判定の線（初回の本番メールが届いた日から）

**判定期間**: 初回の本番メールの日が月曜ならその週から、それ以外なら**翌週の月曜から6週間**（月〜日の週 × 6）。記録は各週の日曜に1回。

| 判定 | 条件（6週間の記録で見る） |
|---|---|
| **続ける** | 投稿3本以上の週が **4週以上** かつ 気持ちの平均が **4.0以上** |
| **やめる** | 投稿1本未満の週が **3回以上** または 気持ちの平均が **2.0以下** |
| **どちらでもない** | 同じ線で **6週間だけ延長**（延長は1回まで）。延長後もどちらでもなければ、そこから先はオーナーの判断 |

- **記録が無い週は投稿0本として数える**（記録が根拠のすべて）。過去8週までは後から記録できる。
- 判定は期間が終わった翌日以降に確定する。**途中では判定しない**（途中経過は表示のみ）。
- **参考**: 投稿した割合 = 投稿数 ÷ 届いた文案の数。低いときに次に直すのは**文面（本人の声への寄せ方）**。仕組みのせいにしない。
- 判定はアイデアや努力の評価ではなく、着手時に合意した線へのルールの適用。

## 👤 本人の作業（3つだけ）

1. **送信用の鍵を発行して Secrets に登録する**
   - Resend: <https://resend.com/signup> で登録（Google / GitHub アカウントでも可）→ 左メニュー **API Keys** → **Create API Key**（Permission: *Sending access*）→ 表示された鍵をコピー
   - GitHub: <https://github.com/brypoai/brypo-landing/settings/secrets/actions> → **New repository secret** で次の2つを登録
     - `RESEND_API_KEY` = いまコピーした鍵
     - `MAIL_TO` = **Resend に登録したメールアドレス**（独自ドメインを認証しない限り、Resend は登録アドレス宛てにしか送れない）
   - 任意: `POST_MAIL_BLOCK_WORDS` = 文案に出てほしくない語をカンマ区切りで（勤務先名など）。この語はログにもメールにも出ない
2. **dry-run を解除して、最初のメールがスマホに届くことを確認する**
   - <https://github.com/brypoai/brypo-landing/settings/variables/actions> → **New repository variable** → `POST_MAIL_MODE` = `live`
   - <https://github.com/brypoai/brypo-landing/actions/workflows/post-mail.yml> → **Run workflow** → `force` にチェック → **Run workflow**
   - 1分ほどでメールが届く。迷惑メールに入っていたら「迷惑メールではない」を1回押す
   - ※ この日が「初回の本番メールの日」になり、判定期間の起点になる
3. **リンクを1回押して、X の投稿画面が本文入りで開くことを確認する**（投稿はしなくてよい）

## 運用メモ

| やりたいこと | 方法 |
|---|---|
| 止める | Variable `POST_MAIL_MODE` を `off` にする（`live` に戻せば再開） |
| 送信時刻を変える | `scripts/post-mail.config.json` の `send_hour_jst` を書き換えて PR → main |
| 届いた中身を確かめる（dry-run 中） | Actions の実行結果 → Artifacts `post-mail-<id>` |
| 鍵を替える | Resend で新しい鍵を発行 → Secret `RESEND_API_KEY` を上書き → 古い鍵を削除 |

- GitHub の定期実行は混雑時に数十分遅れることがある（12:17 起動が 12:40 になる等）。日付が変わる前なら次の起動で送る。
- 費用: Actions（公開リポ）0円、Resend 0円、LLM は既存の1日1回（約 $0.02/日・`/try` と同じ $50/月 上限の内側）。
