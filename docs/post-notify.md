# post-notify.md — 毎日の投稿文案をスマホに通知（＋判定の線）

作成日: 2026-10-11。**この1枚が正本**（仕組み・判定の線・👤の手順）。

## 結論

- `/ops` の「今日の投稿文案」（`/api/post-draft`・1日1本・KV の数値 → LLM）を、**毎日 12:00 JST にスマホへ通知（ntfy）**する。**通知をタップすると、X の投稿画面が本文入りで開く**。
- 消すのは2手だけ: ①サイトを開きに行く ②コピーして貼る。文案の作り方（発生源・プロンプト・1日1回の LLM 呼び出し）は変えていない。
- **自動投稿はしない**。タップで開くのは投稿画面までで、送信ボタンは本人が押す。自動いいね・フォロー・返信・DM も無い。
- **新しい登録・鍵は不要**。使う Secret（`PUBLISH_TOKEN`・`NTFY_TOPIC`）は x-reply.yml 用に登録済みで、2026-09-27 の実行まで動いていたことをログで確認済み。

## 仕組み

| 部品 | 場所 | 役割 |
|---|---|---|
| 定期実行 | `.github/workflows/post-notify.yml` | 毎時 :17 に起動。送るかどうかはスクリプトが判断する |
| 時刻・モード | `scripts/post-notify.config.json` | `send_hour_jst`（初期値 `12`）、`mode`（`dry_run` / `live`）。**数字や文字を書き換えて main に入れるだけで変わる** |
| 本体 | `scripts/post-notify.mjs` | 文案を取得 → 通知を組み立て → 送信（live のときだけ）→ 記録 |
| 文字数・リンク | `functions/api/_xtext.ts` | X の重み付き文字数（twitter-text 準拠・280）、超えたら末尾を切る、`https://x.com/intent/tweet?text=` + URL エンコード |
| ガード | `functions/api/_postnotify.ts` | 価格・有料版・アフィリエイト・メールアドレス・電話番号、＋任意の除外語（Secret `POST_NOTIFY_BLOCK_WORDS`。勤務先名など）に該当した文案は、本文を残してリンクを外す（タップ先は /ops） |
| 記録 | `/api/post-log`（KV `postlog:v1`） | 機械が日ごとの送信本数を記録。日曜に本人が `/ops` で投稿数と気持ち（5段階）を記録 |
| 判定の表示 | `/ops` の「発信の記録」 | 下の線をそのまま当てた結果を表示（期間の途中では判定しない） |

- **通知の中身**: タイトル「今日の投稿文案（10/12 月）」、本文＝文案、タップ＝X の投稿画面、ボタン「X で投稿」「一覧」（日曜は「今週の記録（1分）」も）。
- **既定は dry-run**（通知を組み立てて `out/post-notify/` に書き、送らない）。鍵が無くても動く。
- **停止スイッチ**: GitHub の Variable `POST_NOTIFY_MODE=off` → 次の起動から何もしない。Variable は設定ファイルより優先（`live` / `dry_run` も指定できる）。
- **1日1回**: 送信記録で同じ日の2回目を止める。記録が読めないときは live では送らない（毎時の重複通知を防ぐ）。
- 文案が作れなかった日（予算上限・鍵なし等）は、3時間再試行してから「作れませんでした（理由）」を1件通知する。

### 送信手段の選定（ntfy × GitHub Actions）

| 候補 | 👤の作業 | 判断 |
|---|---|---|
| **ntfy のプッシュ通知（採用）** | なし（Secret は登録済み・アプリは x-reply の通知で使用中だった） | 通知タップ1回で投稿画面が開く。メールを開く手間も無い。無料 |
| Resend のメール（初版で実装・取りやめ） | 登録・鍵の発行・Secret 2つ・切り替え・テスト送信 | オーナーから「大変すぎる」（2026-10-11）。目的は2手を消すことで、メールである必要は無い |
| GitHub の通知 | なし | リポが公開のため、投稿しなかった文案も誰でも読める |

## 判定の線（初回の本番通知が届いた日から）

**判定期間**: 初回の本番通知の日が月曜ならその週から、それ以外なら**翌週の月曜から6週間**（月〜日の週 × 6）。記録は各週の日曜に1回。

| 判定 | 条件（6週間の記録で見る） |
|---|---|
| **続ける** | 投稿3本以上の週が **4週以上** かつ 気持ちの平均が **4.0以上** |
| **やめる** | 投稿1本未満の週が **3回以上** または 気持ちの平均が **2.0以下** |
| **どちらでもない** | 同じ線で **6週間だけ延長**（延長は1回まで）。延長後もどちらでもなければ、そこから先はオーナーの判断 |

- **記録が無い週は投稿0本として数える**（記録が根拠のすべて）。過去8週までは後から記録できる。
- 判定は期間が終わった翌日以降に確定する。**途中では判定しない**（途中経過は表示のみ）。
- **参考**: 投稿した割合 = 投稿数 ÷ 届いた文案の数。低いときに次に直すのは**文面（本人の声への寄せ方）**。
- 判定はアイデアや努力の評価ではなく、着手時に合意した線へのルールの適用。

## 👤 本人の作業

1. **PR をマージする**（その前に「live で」と伝えれば、設定ファイルの `mode` を `live` にしておく）
2. 通知が来たら**1回タップ**して、X の投稿画面が本文入りで開くことを確認する（投稿はしなくてよい）

- 初回はマージ直後に Claude が手動実行（Actions の Run workflow・`force`）で1件送る。この日が判定期間の起点になる。
- 通知が来ないとき: スマホの ntfy アプリで、x-reply の通知を受けていたトピックの購読が残っているかを確認する（アプリを消していたら入れ直して同じトピックを購読）。

## 運用メモ

| やりたいこと | 方法 |
|---|---|
| 止める | <https://github.com/brypoai/brypo-landing/settings/variables/actions> で Variable `POST_NOTIFY_MODE` = `off`（消せば設定ファイルの `mode` に戻る） |
| 時刻を変える | `scripts/post-notify.config.json` の `send_hour_jst` を書き換えて PR → main |
| 出してほしくない語を足す | Secret `POST_NOTIFY_BLOCK_WORDS`（カンマ区切り・任意） |

- GitHub の定期実行は混雑時に数十分遅れることがある。日付が変わる前なら次の起動で送る。
- 費用: Actions（公開リポ）0円、ntfy 0円、LLM は既存の1日1回（約 $0.02/日・`/try` と同じ $50/月 上限の内側）。
